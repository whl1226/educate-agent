## 1. 项目定位

**乡芽**是一款垂直深耕「乡镇 / 县域教育」场景的教育智能体，核心形态是**以 Agent 工作台为中心的四端应用**：教师端、学生端、家长端、管理端共享同一个领域 Agent 大脑，由 AI 自主编排工具完成「理解任务 → 规划步骤 → 调用能力 → 知识增强 → 交付结果」的完整闭环。

与"表单堆功能"的普通 AI 教育应用不同，乡芽把 AI 的**每一步思考、每一次工具调用、每一份证据与引用**都以步骤流形式透明展示给用户——像 opencode / Claude Code 一样"可看见、可追溯、可验证"，让乡镇师生对 AI 结果"看得懂、信得过、用得上"。

产品承诺：简单易用（≤2 步）、真用得上、每个输出可溯源、数据可闭环。

## 2. 目标用户与痛点

| 用户 | 真实痛点 | 乡芽的回应 |
|---|---|---|
| 乡镇教师（常一师多科） | 备课组卷耗时、缺教研资源、照本宣科 | 一键备课 / 一键组卷 / AI 教研员点评，教材引用可溯源 |
| 乡镇学生 | 无人辅导、错题无人讲、缺乏个性化练习 | 苏格拉底式辅导（绝不给答案）、认知诊断、个性化学习计划 |
| 外出务工家长 | 长期在外、祖辈无法辅导、不了解学情 | 脱敏学情周报、语音留言陪伴、祖辈大字版+语音播报 |
| 县域管理者 | 学情不透明、师资缺口、控辍保学压力大 | 区域学情上卷看板、师资预警、控辍保学预警（预警不诊断） |

## 3. 四端功能概览

| 端 | 定位 | P0 核心能力 | 数据闭环特征 |
|---|---|---|---|
| 教师端（14 项） | 工具主角 | 一键备课、一键组卷、一键批改、班级学情看板、AI 教研员 | 教材/图谱/题库知识底座驱动，输出带引用 |
| 学生端（12 项） | 受益端 | 认知诊断、知识问答（RAG+引用）、苏格拉底辅导、错题本 | 作答是唯一原生行为数据源，诊断驱动下游 |
| 家长端（5 项） | 信任陪伴 | 脱敏学情周报、务工留言、大字版播报 | 全部为诊断结果的脱敏视图，无独立数据源 |
| 管理端（7 项） | 治理决策 | 区域学情看板、师资预警、控辍保学预警 | 校级学情上卷，支撑治理决策 |

## 4. Agent 工作台核心体验（步骤流 UI）

乡芽前端新增 `agent.html` 工作台，把 AI 的每一次执行过程以**步骤流**形式实时渲染（SSE 流式推送）：

```
用户提问 → ╔═══ 思考（thinking）═══════╗   ← 折叠块：AI 如何理解任务、规划步骤
           ║ 已识别意图「诊断」，规划：  ║
           ║ ① 执行认知诊断 ② 查错题本 ║
           ╚════════════════════════════╝
           ╔══ 工具卡片（tool card）════╗   ← 可展开：工具名/参数/状态/耗时/结果
           ║ ① run_diagnosis   ✔ 1.2s  ║
           ║ ② get_error_book  ✔ 0.8s  ║
           ╚════════════════════════════╝
           ┌────────────────────────────┐
           │ 流式文本（text_delta）……    │   ← 答案逐字流式输出
           └────────────────────────────┘
           引用 [chunk:12 五上·草船借箭]   ← refs 出处标注，点击可溯源
```

四个交互模型（对应四条 SSE 事件，逐条落库 agent_messages 可回放）：
1. **思考折叠块**：LLM 的意图理解与步骤规划，默认折叠、点击展开——让"AI 为什么这么做"透明可见；
2. **工具卡片**：每次工具调用的名称、参数、执行状态、耗时、可展开的返回结果——全链路证据链；
3. **流式文本**：最终答案逐字流式渲染，低延迟反馈，阅读体验顺滑；
4. **引用 refs**：知识类回答强制标注教材出处（chunk 引用），点击可查看原文片段。

## 5. LangGraph.js 编排架构

```
┌─────────────────────────────────────────────────────────┐
│                 SSE 流式网关 POST /agent/chat             │
│  thinking / tool_start / tool_end / text_delta / done     │
└──────────────┬──────────────────────────────────────────┘
               ▼
┌───────────────────────── LangGraph StateGraph ─────────────────────────┐
│  START → 【intent】意图识别 ──→ 【agent】ReAct 工具循环（≤12 轮）──→     │
│          LLM 分类 + 规则兜底    LLM 自主决定工具与顺序，执行并回填        │
│                                 ──→ 【finalize】引用校验 + 交付摘要 → END │
│  checkpoint-sqlite：多轮会话记忆持久化（与项目 SQLite 同源）             │
└──────────────────────────────┬────────────────────────────────────────┘
                               ▼
┌───────────────────────── ToolRegistry（16 个工具）──────────────────────┐
│ 学生端：run_diagnosis / get_error_book / get_study_plan /              │
│         practice_questions / submit_answer / search_knowledge /        │
│         socratic_tutor / get_latest_diagnosis                          │
│ 教师端：generate_lesson_plan / generate_paper / get_class_overview /   │
│         researcher_comment                                             │
│ 家长端：get_weekly_report      管理端：get_region_overview /           │
│         list_alerts / get_teacher_profile                              │
│ 每步：记录参数 → 执行 → 记录结果 → 计时 → 审计落库（agent_messages）     │
└────────────────────────────────────────────────────────────────────────┘
```

关键技术点：
- **单一领域 Agent 核心**：基于 LangGraph.js `createReactAgent`（ReAct 循环）+ 自定义 StateGraph 包装（意图识别 → 工具循环 → 审查交付），四端 38 项业务能力全部注册为带 JSON Schema 的工具，由 LLM 自主编排，而非各自写死流程；
- **双模式运行**：配置 LLM Key 时走真实 function-calling 编排；无 Key 时自动降级为**确定性规则引擎**（意图规则兜底 + 固定工具序列），保证演示环境离线可跑、结果可复现；
- **SSE 事件协议**：事件行 `event: <type>\ndata: <json>`，前端实时渲染步骤流；全量轨迹（思考/工具调用/结果）落库 `agent_runs` + `agent_messages`，支持历史会话回放与审计；
- **多轮记忆**：LangGraph `checkpoint-sqlite` 把会话状态持久化到现有 SQLite，跨轮对话保持上下文与诊断状态。

## 6. 优秀级知识增强：embedding + BM25 混合 RRF + 引用校验

```
教材分块入库（含章节定位）
   │  每块生成 embedding 向量（OpenAI 兼容模型 / 确定性哈希降级）
   ▼
查询 → 双路召回：BM25（SQLite FTS5） ‖ 向量余弦相似度（embedding）
   ▼
RRF 融合排序（score = Σ 1/(60+rank)）＋ 知识点图谱命中加权（+0.15）
   ▼
输出带 ref 的知识片段（chunk:id） → 引用校验 verifyRefs：LLM 声称的引用
                                  必须命中真实检索集合，否则判定为幻觉
```

- **混合检索优于单一检索**：BM25 保证术语精确命中（教材专有名词），向量召回保证语义泛化（"船借箭为啥要雾天"也能命中"借箭背景"片段），RRF 无需调权重即可稳定融合双路结果；
- **引用校验防幻觉（优秀级标志）**：交付层强制 `verifyRefs`——LLM 回答中出现的每一个引用，必须真实存在于检索返回的集合，否则该引用被剔除并提示"此结论缺乏教材依据"；知识类问题在工具描述中强制要求"必须调用 search_knowledge 并只在返回片段内作答"；
- **可复现降级**：无 API Key 时使用确定性字符哈希特征向量（64 维），同一输入恒得同一结果，演示环境即可展示完整 RAG 链路。

## 7. BKT 贝叶斯知识追踪 与 ZPD 最近发展区算法

**BKT（贝叶斯知识追踪）— 认知诊断引擎**：基于隐马尔可夫模型，把"学生对某知识点的掌握状态"建模为隐变量，用作答序列在线更新：

- 模型参数：初始掌握概率 P(L₀)、学习转移概率 P(T)、猜测率 P(G)、失误率 P(S)；
- 每道题作答后，用贝叶斯后验更新 P(L)：`P(L₁) ∝ P(观测|L₁)·P(L₁)`，输出**掌握度 + 置信度 + 证据题数**；
- 可解释、可复现、可审计：每个诊断结论都能回答"基于哪几道题、当前置信度是多少"，契合"不凭空出现"原则。

**ZPD（最近发展区）— 个性化学习路径**：依据维果茨基理论，练习难度应落在"学生现有水平之上、通过引导能够达到"的区间：

- 诊断结果 → 确定已掌握区 / 最近发展区 / 未知区 → 学习计划只推**最近发展区**的知识点；
- 每轮作答回流更新 BKT 参数 → 计划动态调整难度与路径 → 再次作答（闭环回流）；
- 配合苏格拉底辅导状态机：引导式提问 + 规则层拦截答案，学生"跳一跳够得着"，不挫伤也不停滞。

## 8. 数据闭环：作答 → BKT → 上卷视图

```
学生作答（唯一原生行为数据源）
   ▼ 采集 → 脱敏 → 入库
BKT 认知诊断（掌握度+错因+置信度）
   ├─→ 学生端：学习计划（ZPD）→ 推送练习 → 再作答（回流闭环）
   ├─→ 学生端：错题本（错因沉淀）
   ├─→ 教师端：班级学情看板（班级聚合）
   ├─→ 家长端：学情周报（脱敏视图）
   └─→ 管理端：区域看板（校级上卷 → 师资/控辍预警）
```

设计原则："一源多视图"——**所有学情类输出都是作答数据的脱敏聚合**，不存在凭空出现的掌握度；每个输出可回答"数据从哪来 → 怎么算 → 输出什么 → 依据在哪"。

## 9. 安全合规边界

| 合规项 | 具体措施 |
|---|---|
| 未成年人保护 | 学生数据全链路脱敏；心理关怀 / 控辍预警 / 防欺凌模块**只预警、不诊断、不贴标签**，人工介入兜底 |
| 不替代教师评价 | AI 批改 / 学情结论均为"辅助+建议"，关键结论须教师确认采纳（采纳动作留痕） |
| 不给答案 | 苏格拉底辅导规则层拦截直接答案，只做分步引导 |
| 模拟数据标注 | 演示用学情数据均标注「模拟数据 Demo」，来源、授权、边界在需求汇总表 v4 中列明（D1–D7 数据源清单） |
| 系统安全 | CSRF + 重放 + 限流 + JWT 双 Token + RBAC 数据域校验 + 上传魔数校验 + 输出编码防 XSS（详见《安全设计说明》） |
| AI 内容边界 | 知识回答强制引用校验防幻觉；不提供医疗 / 心理诊断等越界结论 |
