## 3. 详细设计

### 3.1 全局交互绑定层（P0 · 横切修复）

**问题**：radio-pill span、switch、opt-card 等交互在 teacher.html 中依赖内联 onclick 或完全没有绑定。

**方案**：在 `teacher-main.ts` 增加 `bindGlobalControls()`：
- 对 `.radio-pill > span`：统一 click → 兄弟 span 去 `.on`，自身加 `.on`（与 agent-presets.bindPresetForm 同款逻辑）
- 对 `.switch`：统一 click → toggle `.on`（替代失效的 `onclick="this.classList.toggle('on')"`；HTML 中原内联 onclick 由 legacy CSP 层静默跳过，无需删除）
- 对 `.opt-card`：统一 click → 组内去 `.sel` 自身加 `.sel`（部分页面已有 inline onclick 如 `selQ`，存在内联绑定的用 `onclick` 自有逻辑，不重复绑定——判定：若元素已绑过（CSP 层 `__boundOnclick`）则跳过）
- 保留 makePill/togglePick 等既有函数；新增的筛选/联动逻辑见各模块

**验收**：teacher.html 内所有 radio-pill、switch 可点击切换且视觉正确；paper 页"分层模式"3 个选项可切换，下方 2 个 switch 可开关；micro 页提词卡 switch 可用。

### 3.2 历史教案 / 教案库（P0 + 后端小改）

**现状**：`GET /lesson-plans` 列表无 content；无详情接口；列表行无点击。

**方案**：
1. 后端：`GET /lesson-plans/:id`（@Roles teacher/admin）返回单条完整教案（content/outline/sourceRefs）；列表响应**附加 `runId`**（lesson_plans 表新增 `run_id` 列，nullable，由 generate_lesson_plan 工具落库时写入；老数据为 null）
2. 前端：`loadLessonList()` 改造为「历史教案」列表 +「教案库」卡片区：
   - 每行 list-row 变为可点击（cursor:pointer + hover 提示"点击查看/继续追问"）
   - 点击行为：`runId 存在` → `location.href = 'agent.html?conv=' + runId`（打开会话回放，可继续追问）；`runId 为空` → 打开详情模态（GET /lesson-plans/:id 渲染 content JSON 结构化展示：教学目标/重难点/环节时间线），模态底部按钮「继续追问智能体」→ 跳 agent.html 并自动填充"基于《topic》教案，帮我……"
3. 「教案库」：右侧卡片区标题改「教案库」，显示全部教案（数量 chip），支持按学科/课题过滤（前端过滤即可），点击同上述行为

**验收**：有 runId 的教案点击 → agent.html 打开对应会话并可继续发送追问；无 runId → 详情模态正常渲染；教案库卡片数与 /lesson-plans 列表一致。

### 3.3 智能组卷（P0）

1. **分层模式可切换**：3.1 全局绑定修复（radio-pill + switch）
2. **试卷预览来源说明**：预览卡片 head 增加 src-tag/cite："预览由智能体组卷结果回填 · 数据源 /papers export"；chip 展示题数（已有）
3. **下载按钮引导**：
   - 无试卷时：按钮保持 disabled，标题 tooltip 已有；增加**提示条**（预览卡片空态区）："点击「发送给智能体」完成组卷后可下载 Word/PDF"
   - 有试卷但下载失败/未生成文档：toast 文案优化
4. （可选增强，P1）点击下载时若 /papers 存在但文档未生成 → 后端 download 接口本会即时生成（teacher.service.ts:316-358 现生成现返回），无需预生成

**验收**：分层模式三选项可切换；预览卡片显示来源说明；无试卷时下载按钮禁用且页面有引导文案；有试卷时下载 docx/pdf 成功。

### 3.4 AI 教研员（P0 交互 + P1 文件解析）

**P0 交互修复**：
1. **讲题话术（resTab1）**：`togglePick` 选择题目后，`data-send-agent="res1"` 发送时**带上所选题目**——SEND_AGENT.res1 改为 `(form) =>` 读取页面 `#resTab1` 中被选中的题目文本（.list-row 选中态），构造任务文本；未选择时 toast 引导"请先选择题"；去掉硬编码
2. **教学建议（resTab2）**：增加「发送给智能体」按钮（data-send-agent="resAdvice"），任务模板基于班级学情生成教学建议（复用 SEND_AGENT.skills 式固定模板：班级掌握度 71%、薄弱点统计与可能性 58% 等，或调用后端 /ai/researcher/advice）；页面下方空态区显示生成结果（复用 res0-result 模式）
3. **统一开关**：三个 tab 均有独立的发送按钮与结果区，交互一致

**P1 文件解析（用户已确认：后端解析→文本注入）**：
1. 后端：files 模块 document 分类魔数白名单扩展 **docx**（mime application/vnd.openxmlformats...）；新增 `POST /files/extract-text` 接口（入参 fileId）：
   - docx：新增依赖 `mammoth`（纯 JS，无系统依赖）→ extractRawText
   - pdf：新增依赖 `pdf-parse`（node 版，注意渲染为纯文本）→ text
   - 上限复用 document 10MB；安全：仅提取文本不存结果文件，文本长度截断（如 20k 字符）
2. 前端教研员 tab0：textarea 上方加「上传 Word/PDF」上传区（复用 upload-zone 样式，`POST /files/upload?category=document` → `/files/extract-text`）→ 提取文本**填入 textarea**（可编辑再发送），并显示来源文件名 chip；非 docx/pdf 文件 toast 拒绝
3. 任务文本不变（res0 buildTask 已有 sourceContent），智能体链路零改动

**验收**：上传 docx 后 textarea 自动填充其文本并可发送；pdf 同理；非法类型被拒；讲题话术发送的任务包含所选题目；教学建议 tab 可生成结果。

### 3.5 基本功诊断（P0）

**根因**：toast 被 wiz-mask 遮挡；step0 校验过严。
**方案**：
1. **toast z-index 修复**：teacher.html `.toast{z-index:200}` → `z-index:400`（高于 wiz-mask 300）；agent.html 同步检查（agent.html 内如无 wiz 则不需要）
2. **校验引导优化**：
   - step0：未选满 8 项时，除 toast 外**高亮未选择的自评行**（加 .miss 样式：边框 rose + 抖动动画），并提示"还差 N 项"
   - step1/step2：未答时对应问题区块加 .miss 高亮
   - legacy.js skillNext 增加高亮逻辑（新增函数 markMiss(...)/clearMiss()）
3. **支持跳过部分自评（可选）**：维持 8 项必选（训练计划需要全维数据），但明确反馈

**验收**：向导打开时 toast 可见（在遮罩之上）；未完成时下一步有 toast + 红色高亮提示；全完成后正常进入生成动画。

### 3.6 教学资源库（P0 筛选 + P1 联动/上传/权限）

**P0**：
1. 顶部类型/权限筛选真实生效：`GET /resources?type=&license=` 后端支持过滤（controller/service 已支持 type；补 license 参数），前端 makePill 切换 → 重新请求渲染；空态提示"该分类暂无资源"
2. 资源卡点击 → 打开详情模态（名称/类型/授权/描述/下载次数/下载按钮 GET /files/:id/download）

**P1 权限与联动**：
1. **权限类别模型**（license 字段扩展为四类，与现有数据兼容）：
   - `自建`：仅本人可见（列表默认过滤：他人不可见）——现 default
   - `共享`：组内（同校）可见 —— 新增值
   - `公开领域`：全员可见
   - `CC BY`：开放授权，全员可见并标注来源
   - 前端筛选 tabs：全部 / 我上传的（自建）/ 共享 / 公开领域 / CC BY；上传时选择类别；后端 GET /resources 增加 license 过滤 + 权限可见性校验（service 现有逻辑已按 teacherId 返回本人资源，扩展可见规则）
2. **生成自动入库**：agent 端 `generate_lesson_plan` 工具落库时**同时写入 resources 表**（type=教案，license=自建，fileId 关联生成文档）；`generate_paper` → type=习题；PPT 生成（generate_document format=pptx 且标题含"课件"）→ type=课件；实现方式：工具内落库逻辑扩展（tool-registry 内 generate_lesson_plan/generate_paper 的 handler）
3. **微课视频上传**：上传区 `POST /files/upload?category=video`（已支持 mp4 100MB）→ 返回后 `POST /resources`（type=视频，fileId）→ 列表刷新；资源卡视频类显示时长/播放样式（点击播放走 /files/:id/download 或内联 video 标签预览）
4. 上传表单模态：名称/描述/类型/授权类别/文件 → 创建资源

**验收**：筛选真实过滤；生成教案后资源库自动出现"教案"记录；上传 mp4 出现"视频"资源卡；不同 license 可见性符合模型。

### 3.7 家长会材料：历史发言稿跳转（P0）

**方案**：
1. 后端：speech_docs 表加 `run_id` 列（nullable），`POST /ai/speech/generate` 落库时写入；列表接口返回 runId
2. 前端 `loadSpeechDocs()`：list-row 可点击 → runId 存在 → `agent.html?conv={runId}`；为空 → 弹详情模态（GET /speech-docs 已有 content 全文）＋"继续追问"按钮
3. 与 3.2 共用同一跳转/模态工具函数（新建 `src/frontend/core/conv-jump.ts` 或 teacher-main.ts 内共享函数）

**验收**：点击"已保存"发言稿 → 打开对应会话可续聊（或详情模态）。

### 3.8 开学材料包：预览/编辑（P0）

**方案**：
1. **真实文档预览**：6 张卡片按钮统一改为打开预览模态——模态内加载模板内容（`GET /back-to-school/package` 的 items 已有 preview 摘要；扩展 items 返回完整 content：templates 表已有 content 字段）
2. **预览模态**：渲染模板 content（Markdown → 简单 HTML，复用 agent 端 mdToHtml 逻辑抽为共享 util）＋头部"此材料由模板生成，可发送智能体优化"引导按钮 → 跳 agent.html 预填"请优化开学材料《班级公约》：……"
3. **编辑**：模态内 textarea 可编辑，保存 → `PATCH /back-to-school/package/:id` 或本地模板表更新（后端 templates 表无 PATCH，新增轻量接口）→ toast 已保存
4. 后端：`GET /back-to-school/package` items 增加 `content`（templates.content 全文）；新增 `PATCH /back-to-school/package/:id`（按模板 id 更新 content）

**验收**：每张卡预览/编辑可打开真实内容；编辑可保存；一键打包按钮保留（下载全部模板文档——可选，P1 若时间紧则保持 toast）。

### 3.9 留守儿童沟通：场景联动（P0）

**方案**：
1. 顶部 radio-pill 改为场景切换（保留 makePill 高亮 + 新增联动）：点击"视频通话开场/孩子情绪低落/学习督促/监护人沟通/敏感话题" → 下方卡片区**按场景过滤/排序**（卡片 data-scene 属性；当前 5 张卡片各属一个场景，点击后仅显示对应场景卡片，其他隐藏或置灰）
2. 知识库卡片（loadKnowledgeBase 渲染的"知识库·家校沟通要点"）也按场景过滤
3. 卡片增加"复制话术"按钮（navigator.clipboard + toast"已复制"）——提升实用感
4. 空场景处理：某场景无卡片时显示"该场景话术生成中，可让智能体生成"引导按钮

**验收**：点击 5 个场景 tab，下方卡片区内容对应切换；复制按钮可用。

### 3.10 职称材料整理：真实上传 + 自动分类（P0 核心 + P1 分类增强）

**方案**：
1. **真实上传**：upload-zone 改为真实文件选择（hidden input multiple + drag/drop）→ `POST /files/upload?category=document`（pdf/doc/docx/jpg/png 已支持）逐个上传 → 已上传文件列表（文件名/大小/状态 chip）→ 全部上传完成后显示"发送给智能体自动分类"按钮（data-send-agent="title"，任务文本拼接文件名清单）
2. **本地即时分类预览（演示层）**：上传完成后按扩展名/文件名关键词做**前端启发式预分类**（获奖证书/论文课题/继续教育/任职教案 四类桶，文件名匹配关键词如"证书/奖/论文/结业/教案"），展示在右侧结果区（带"AI 智能分类"chip 与"查看"占位）；点击「发送给智能体」→ 智能体正式分类（现有 title 任务）
3. **UI 优化**（使用 frontend-design/ui-ux-pro-max 技能）：上传区更明显的拖拽态（dragover 高亮）、文件队列（缩略图标+大小+删除）、分类结果用四象限/标签墙呈现、进度动画
4. 结果区数据持久化：上传文件列表存 sessionStorage（刷新不丢），分类结果存 localStorage 键 `xy.title.result`

**验收**：可真实上传多文件；拖拽生效；上传后文件队列展示；分类桶出现启发式预分类结果；发送智能体任务含文件名清单。

### 3.11 线上集体备课：多人协同演示（P1 · 重点项目）

用户要求：多人协作演示 demo，效果极致，含 AI 教研员辅助。

**方案**：
1. **数据模型**（后端最小扩展）：

### 3.12 agent 会话深链 + 续聊（P1 · 支撑 3.2/3.7）

**现状**：agent.html 无 URL 参数解析；/agent/chat 每次新建 run；无续聊。
**方案**：
1. 前端：`agent-main.ts` 解析 `URLSearchParams` 的 `conv`：
   - 有 conv → 校验归属（GET /agent/runs/:id 已含越权校验）→ 加载回放（switchToHistory）→ **输入框激活**，发送时请求体带 `runId`
   - 无 conv → 原逻辑
2. 后端：
   - `AgentChatDto` 增加可选 `runId?: number`
   - `stream()`：有 runId 时——校验 run 存在且属于当前用户（失败抛 SCOPE_FORBIDDEN）；加载该 run 的 messages（取用户 task + final 文本，最多最近 3 轮）；新 run 的 `taskInput` 记 `[续聊 run#{id}] {text}`；LLM 模式把历史摘要拼入 messages 首条（human 前追加 assistant 历史）；demo 模式 detectIntent 基于新 input 不受影响
   - 展示：前端回放列表保留历史消息 + 追加新 run 的流式消息（新 run 的 runId 会变——**回放视图用 session 内拼接**：历史消息（旧 run）+ 新消息（新 run），切换轨迹 tab 显示新 run 轨迹）
3. 备注：不做同一 run 的 thread 续接（避免 checkpointer 状态污染），采用"新 run + 历史上下文注入"的轻量方案，行为等价且稳定

**验收**：agent.html?conv=5 打开 run#5 回放，输入"再优化一下导入环节"发送 → 新 run 响应包含历史上下文语义（demo 模式至少任务文本携带历史摘要）；无权限访问他人 run 被拒。

## 6. 风险与说明

- **pdf-parse 兼容性**：node 20 下 OK；若安装/解析异常，pdf 提取降级为"提示不支持，建议 docx"（功能开关）
- **mammoth 纯 JS**：无系统依赖，风险低
- **resources 自动入库**：仅 demo/LLM 生成链路写入，不影响既有资源数据
- **续聊上下文**：demo 模式带历史摘要文本，LLM 模式拼接 messages，均不影响原 run 数据
- **collab 演示脚本**：模拟批注为前端定时器注入（仅当前浏览器会话），真实批注走 API 持久化；两套并存不冲突
- **CSP**：新增按钮全部走 data-send-agent / addEventListener，不新增内联 onclick（避免 CSP 层坑）
