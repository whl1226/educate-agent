# 乡芽 · 乡镇教育智能体 — 安全设计说明

## 1. 威胁模型

系统面向乡镇教育场景（未成年人数据敏感），按高于普通商业项目的标准防御：

| 威胁 | 防护层 |
|---|---|
| 撞库 / 暴力破解 | 登录限流 10 次/15 分钟/账号+IP |
| 跨站请求伪造 (CSRF) | 双提交 Cookie + 自定义头，三重兜底 |
| 请求重放 | 时间戳窗口 5 分钟 + 一次性 Nonce + HMAC 签名 |
| SQL 注入 | better-sqlite3 全参数化 + DTO 正则白名单 |
| XSS（存储型） | 输出编码（前端统一 esc）+ CSP + 服务端不信任输入 |
| 越权访问 | 全局 RBAC 守卫 + 数据域校验（班主任/家长关系/管理员） |
| 上传投毒 | 魔数校验 + 扩展名白名单 + 大小限制 + 隔离目录 |
| Token 窃取/篡改 | JWT 签名校验 + 会话管理 + 全端登出 |
| 敏感信息泄露 | 统一异常过滤器（不返回堆栈）+ 手机号掩码 + 密码 bcrypt |

## 2. 守卫链（全局，按序执行）

```
CsrfGuard → ReplayGuard → RateLimitGuard → JwtAuthGuard → RbacGuard
```

- **CsrfGuard**：非 GET 请求要求 `X-CSRF-Token` 头 == `XSRF-TOKEN` Cookie；无 Origin/Referer 的请求（如原生客户端）跳过来源校验但仍校验 Token；登录后 Cookie 轮换。
- **ReplayGuard**（`@ReplayProtected`）：要求 `X-Timestamp`（|t-now| ≤ 5 分钟）、`X-Nonce`（10 分钟一次性）、`X-Signature = HMAC(SIGNING_SECRET, "METHOD|/api/v1|path|ts")`；重复 Nonce 或过期时间戳返回 40304/40303。
- **RateLimitGuard**（`@RateLimit`）：滑动窗口计数，Redis 可用时用 Redis，否则内存。
- **JwtAuthGuard**：Access Token（15 分钟）→ 失败尝试 Refresh（HttpOnly Cookie，7 天）→ 再失败 401。
- **RbacGuard**：`@Roles('teacher'|'student'|'parent'|'admin')` 路由级角色控制；业务层再做数据域校验（如家长只能看自己孩子、教师只能看自己班级）。

## 3. 认证与会话

- 密码 bcrypt 哈希存储；登录失败不区分用户/密码错误原因。
- Access：JWT 短时；Refresh：HttpOnly + Secure + SameSite=Lax Cookie。
- 会话记录支持：查看会话列表、撤销指定会话、全端登出、强制下线（管理员）。
- 密码修改需旧密码；重置走限流验证码流程（3 次/15 分钟）。

## 4. 上传安全（files 模块）

- 分类白名单：image/audio/video/document/text；扩展名白名单按分类。
- **魔数校验**（MAGIC 表）：JPEG `ffd8ff`、PNG `89504e47...`、GIF、MP3 `494433`、Ogg、RIFF、MP4、PDF `25504446`、OLE `d0cf11e0...`——伪装扩展名直接拒绝（实测：伪装 .jpg 文本文件 → 400「文件内容与声明类型不符」）。
- 大小限制：image 8MB / audio 20MB / video 100MB / document 10MB / text 1MB。
- 存储目录与静态挂载一致（`server/uploads`，`/uploads` 前缀），文件名服务端生成。

## 5. 前端防御

- **统一输出编码**：`core/xss.ts` 的 `esc/escAttr/nl2br` 用于全部动态渲染（模板字符串一律转义，已验证 XSS 载荷 `<script>` 原样存储、渲染时转义不执行）。
- CSP：`default-src 'self'`、`script-src 'self'`（无内联脚本执行）、`img-src 'self' data:`、`style-src 'self' 'unsafe-inline'`（原型内联样式所需）、`connect-src 'self'` 等。
- 登录/请求封装（`core/request.ts`）：自动携带 CSRF 头、签名、Nonce；401 自动刷新重试一次。
- 页面级角色守卫（`core/guard.ts`）：角色不符重定向至该角色首页（实测学生访问 admin.html → 弹回 student.html，管理端 DOM 不渲染）。
- 上传（`core/request.ts upload()`）：multipart + 安全头齐备。

## 6. 限流参数

| 接口 | 限额 |
|---|---|
| POST /auth/login | 10 次 / 15 分钟 |
| POST /auth/refresh | 30 次 / 15 分钟 |
| POST /auth/password/reset-request | 3 次 / 15 分钟 |
| POST /auth/password/reset | 5 次 / 15 分钟 |

## 7. 自检结论（2026-08-14，11/11 通过）

| 项目 | 结果 |
|---|---|
| SQL 注入（用户名/密码载荷） | 被拒（40001 校验 / 401 认证失败，参数化查询） |
| XSS 载荷存储回显 | 原样存储、服务端不执行不剥离，前端转义防御 |
| 伪装 .jpg（魔数） | 400 拒绝；真实 PNG 正常通过 |
| 缺少 CSRF 头 | 40303 |
| 签名/Nonce 重放 | 40304 |
| 篡改 Token | 40101 |
| 学生访问管理接口 | 40301 |
| 登录爆破 | 429（6 次连续失败后触发） |

## 8. 遗留风险与改进建议

1. `SIGNING_SECRET` 客户端可见（构建注入）：生产应升级为服务端短时挑战或设备指纹签名。
2. SQLite 单文件库：生产建议迁移 PostgreSQL/MySQL 并启用 TypeORM 迁移。
3. 未配置 Redis 时限流为进程内存，多实例部署必须启用 Redis。
4. iconify 图标走公网 CDN：内网部署需自托管图标库或离线图标。
